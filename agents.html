研报知识库 · 维护规范（schema）

这是一个专用研报知识库：券商研报、第三方行业研究、调研纪要等投研材料，由 Codex 增量构建并持续维护。人负责投喂研报与提问，你（Codex）负责一切加工、归档、交叉对比与簿记。

核心理念：研报是带时效的观点，不是稳定的知识。 本库不做概念图谱式拆解，而是做观点档案：结构化卡片 + 实体时间线。核心属性永远是”谁说的、什么时候说的、基于什么假设”。

核心原则

  1. 三层分离：raw/ 源文层只读不改，是事实来源；wiki/ 由你全权维护，人只读；AGENTS.md 是 schema，人机共同演进。
  2. 卡片是唯一真相源：任何索引（未来的 SQLite/向量层）都只是可重建的缓存。
  3. 分歧是信息不是噪声：多机构观点冲突时并排陈列、标注时间，永不静默调和或覆盖。
  4. 默认自动入库：飞书管道投递的研报直接按本规范处理并在 log 记录，人抽查；人可指定某篇走”先过要点再落盘”的人工模式。

目录结构

raw/assets/        复杂图表的页面截图

wiki/companies/    公司页
wiki/industries/   行业/主题页
wiki/index.md      索引（按行业分组，每篇一行）
wiki/log.md        append-only 日志
templates/         卡片骨架
_archive/          非投研的历史内容归档

卡片 frontmatter

分类路由（入库第一步：判断类型 → 选骨架）

报告类型骨架详略
公司首次覆盖 / 深度templates/公司报告.md详细
业绩点评 / 事件点评 / 调研纪要 / 周报跟踪templates/点评纪要.md精简，核心是”增量信息”
行业深度 / 专题templates/行业报告.md详细，核心是”假设链”
宏观 / 策略 / 固收 / 金工templates/宏观策略.md中等
无法归类（招股书分析、ESG、专家访谈等）不硬套模板，保必填字段，按报告自身逻辑组织—

模板是骨架不是表格：报告没有的章节删掉，模板没覆盖的高价值内容自行加节。判断标准：三个月后不翻原文，这张卡能否还原报告的核心价值。

Ingest 工作流

  1. 去重：查 raw/ 是否已有同名（去时间戳前缀比对）或同内容（md5）文件。重复则不入库，log 记一条 dedup。
  2. 读原文：Codex 直读 PDF（视觉通道）。扫描件或表格严重破碎的，先告知用户解析质量问题，不硬生成低质卡片。
  3. 分类路由 → 选骨架，写卡片，遵守以下加工规则：
    • 事实/观点分离：财务数据、已发生事件是事实；预测、评级、“我们认为”是判断，必须写明”XX机构预计/认为”。
    • 假设链提取：任何空间测算，把关键假设（渗透率、时长、单价、增速）单独列出——结论会过时，假设链可用新数据代入复用。
    • OCR 修正：网络转载 PDF 常见噪声（“合作”→“合报”、“政策”→“府策”、书名号丢失）按上下文修正；不确定的保留原文加 [?]；来源质量差的在卡首注明。
    • 第三方警示：source_quality: third_party 的，卡首注明”数据为第三方机构测算，可信度需自行判断”，激进测算单独点出。
    • 与前篇对比：先检索同 company / industry 的历史卡片，如有，卡尾写”与前篇观点对比”（评级/目标价/逻辑/假设变化）；跨机构分歧用 > ⚠️ 显式标注。
  4. 更新实体页（见下节）。
  5. 更新 index.md：对应行业分组下登记一行：[[卡片]] — report_date · 机构 · 评级/目标价 · 一句话论点。改完 wiki/index.md 后，同步覆盖根目录 index.md（两者内容必须一致，根目录那份是 Obsidian 首屏入口的镜像）。
  6. 追加 log.md：## [日期] ingest | 标题，列出写了/更新了哪些页面。

表格与图表（视觉转写）

  • 核心表格（盈利预测、测算、估值对比、竞争格局）完整转写为 markdown 表；附录三大报表只提取高频行（收入/净利/毛利率/ROE/经营现金流），注明”完整见原文PX页”。
  • 转写自校验：抽查 2-3 个数字比对原文；有合计关系的表验证勾稽，对不上重新核对。
  • 图表三级：①带数据标签的柱/饼图 → 转数据表；②无标签趋势图 → 只写标题+数据来源+趋势+可确认点位，严禁估读精确数值；③复杂结构图（产业链图谱、架构图）→ 该页导出图片存 raw/assets/，卡内 ![[assets/...]] 嵌入并配文字说明。
  • 溯源：转写的表/图标注 （原文P12·图表16）；回答涉及具体数字且卡片信息不足时，按页码回读 raw/ 原 PDF 核实，不凭卡片外推。

实体页维护

建页门槛（先判断，够格才建）：只有满足下列之一才建独立公司页——① 是某篇报告的主标的（卡片 company 字段）；② 被 ≥2 篇报告实质讨论（有专门段落/测算，不只是 related_companies 列表里带一笔）。仅被”提及”（列在相关标的、一句话带过）的公司不建页，只在对应行业页正文里留 [[链接]]（保留 wikilink 占位即可，Obsidian 显示为未解析链接是正常的；该标的日后够格建页时，所有既有链接自动生效——所以别改成纯文本）。非投资标的实体（券商、央行如美联储、交易所、报告发布方/平台如阿里国际站、慧博/头豹等第三方机构）一律不建公司页。

新公司升格：某个原本只在行业页留链接的标的，出现第 2 篇实质讨论时，才从行业页”毕业”建独立公司页，并把行业页里的相关要点迁入。

公司页（wiki/companies/，一司一页）：

  • 公司速览（业务、地位、股权、竞对——事实层，随新研报增量修订）
  • 评级与目标价时间线（本库最值钱的衍生数据）：| report_date | 机构 | 类型 | 评级 | 目标价 | 核心观点 | [[卡片]] |，按日期排序
  • 关键分歧跟踪（各家不一致的点，⚠️ 标注）
  • 待验证的催化剂（checkbox 列表，验证后勾选并注明结果）

行业/主题页（wiki/industries/，如”存储芯片""AI算力产业链”）：

  • 产业链地图与环节关系（可嵌截图）
  • 该行业的研报时间线（同上表格式）
  • 跨公司/跨机构的横向对比与核心争议

Query 规则

  1. 检索策略：实体明确 → grep frontmatter（company/broker/rating/report_date）；对比演变类 → 先读公司/行业页时间线；模糊语义 → 先读 index.md 定位候选再精读卡片。
  2. 每个观点标注：机构名 + report_date。多机构冲突并列呈现。
  3. 时效提醒：引用超过 3 个月的目标价/盈利预测/高频数据，主动提醒可能过时。
  4. 可信度区分：third_party 数据引用时注明来源性质。
  5. 好答案回填：有价值的对比分析、横向梳理，回填成 industries/ 主题页或追加到实体页，别让探索消失在聊天里。
  6. 不做投资建议：可转述研报观点及逻辑，但明确说明是研报观点、不构成建议。

Lint（定期体检）

  • 过期观点：目标价/预测超过 6 个月未更新的公司页，标注”覆盖陈旧”
  • 催化剂对账：到期的催化剂是否已验证/证伪，回填结果
  • 矛盾扫描：新卡与实体页既有结论的未标注冲突
  • 覆盖空白：被多篇行业报告提及却没有公司页的标的
  • 孤儿卡：未被任何实体页链接的卡片
  • 主动建议：值得补的研报方向、值得新建的主题页

演进路线（规模触发，未到不做）

  • 卡片 > ~300 张：建 SQLite frontmatter 索引脚本（结构化查询加速），索引可随时重建
  • 卡片 > ~1000 张：对卡片”一句话论点+核心逻辑链”建向量索引（语义召回），召回后仍走精读
  • 任何阶段：markdown 卡片是唯一真相源，索引坏了删掉重建
