RAG（检索增强生成）

RAG（Retrieval-Augmented Generation，检索增强生成）= 检索技术 + LLM 提示。 先从知识库检索出与问题相关的资料，把资料和问题一起注入提示词，再让大模型参考这些资料生成回答。

这是本页的核心枢纽，串联起 RAG 的各个子技术。源文见 2026-06-29-RAG检索增强生成含高级方法。

为什么需要 RAG

通用大模型有三个痛点，RAG 对症下药：

痛点说明RAG 如何解决
知识局限模型只知道训练数据，不懂私域/实时信息检索补充外部知识
幻觉模型会一本正经地胡说给它真实资料作依据
数据安全私有数据不愿上传训练数据留在自己库里，仅检索时用

两个阶段

  • 数据准备（离线）：数据提取 → 文本分割（chunking）→ 向量化（embedding）→ 数据入库。详见 向量检索与Embedding。
  • 应用（在线）：用户提问 → 数据检索召回 → 注入 Prompt → LLM 生成答案。

Naive RAG（最简形态）

最朴素的实现：文本分块 → 用 encoder 嵌入为向量 → 入索引 → 查询时同样向量化 → 搜索 top-k → 把对应文本块作为上下文喂给 LLM。

从 Naive 到 Advanced RAG

高级 RAG 在检索前后增加了多个增强环节（下图绿色为核心技术）：

  • 检索前/检索中：分块与向量化、分层索引、HyDE / 假设性问题、内容增强（语句窗口 / 父文档检索）、混合搜索
  • 检索后：重排与过滤
  • 查询侧（LLM 推理）：查询转换（子查询拆分、Step-back、查询重写）、查询路由、RAG融合
  • 系统化：聊天引擎（对话上下文）、Agent 智能体、响应合成

评估：RAG 三元组

衡量一个 RAG 系统的三个关键指标：

  1. 检索内容相关性 — 检索到的上下文是否相关（最关键、最可控）
  2. 答案基于性 (groundedness) — 答案在多大程度上被检索上下文支持
  3. 答案相关性 — 答案是否回应了问题

常用框架：Ragas、TruLens、LangSmith。
