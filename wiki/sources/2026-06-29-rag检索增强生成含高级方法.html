一文读懂：大模型 RAG（检索增强生成）含高级方法

源文摘要页。原文是一篇系统讲解 RAG 的长文，主要参考 LlamaIndex 的实现，从基础概念一路讲到高级技术、RAG 融合、微调与评估。核心概念见 RAG。

核心要点

  • RAG = 检索技术 + LLM 提示。从私域知识库检索相关信息，注入 Prompt，让大模型参考资料生成回答。
  • 解决三大痛点：知识局限（模型不懂私域/实时数据）、幻觉（一本正经胡说）、数据安全（私有数据不上传训练）。
  • 两个阶段：
    • 数据准备（离线）：数据提取 → 文本分割 → 向量化 → 数据入库
    • 应用（在线）：用户提问 → 数据检索召回 → 注入 Prompt → LLM 生成答案

高级 RAG 技术（原文重点）

原文主要参考 LlamaIndex，系统梳理了高级 RAG 的核心环节（下图绿色为重点技术）：

  1. 分块 (Chunking) & 向量化：块大小取决于 embedding 模型 token 容量（BERT 类 ~512，OpenAI ada-002 ~8191），需在”上下文足够推理”与”嵌入足够具体”间权衡。详见 向量检索与Embedding。
  2. 搜索索引：平面索引（暴力计算）→ 向量索引（FAISS/nmslib/annoy，基于 ANN：聚类/树/HNSW）；分层索引（摘要索引 + 块索引两步检索）；假设性问题与 HyDE；内容增强（语句窗口检索、父文档检索）。
  3. 重排 (reranking) 与过滤：检索后用相似度/关键词/元数据/交叉编码器/Cohere 重排接口完善结果，是送入 LLM 前的最后一步。
  4. 查询转换：用 LLM 把复杂查询拆成子查询、Step-back prompting（生成更通用查询）、查询重写。
  5. 聊天引擎：引入对话上下文（ContextChatEngine、CondensePlusContextMode）。
  6. 查询路由：LLM 决策下一步该做什么、查哪个数据存储。
  7. 智能体 (Agent)：多文档 Agent 方案（每文档一个 Agent + 顶层 Agent 综合），强大但慢。
  8. 响应合成：把上下文与查询拼接给 LLM，或多次调用优化答案。

混合搜索 / 融合检索

结合关键词检索（稀疏，如 BM25/tf-idf）与向量检索（语义），用 Reciprocal Rank Fusion (RRF) 合并重排。详见 混合搜索与重排。

RAG 融合的取舍

  • 优点：上下文更多样、额外控制层、自动纠错、（相对）成本可控。
  • 缺点：延迟增加、行话/内部术语下自动纠错可能帮倒忙、收益不明时成本浪费。
  • 详见 RAG融合。

微调与评估

  • 微调：编码器微调（对 bge-large 提升有限）、排序器（交叉编码器）微调、LLM 微调（RA-DIT 同时调 LLM + Retriever）。
  • 评估：RAG 三元组——检索内容相关性、答案基于性（groundedness）、答案相关性。框架：Ragas、TruLens、LangSmith。

工具生态

  • 框架：LlamaIndex、LangChain、Dify
  • 向量库：见 向量数据库（FAISS、Chroma、Weaviate、Pinecone、Milvus、ES）
  • Embedding 模型：见 向量检索与Embedding（OpenAI、ERNIE、M3E、BGE、E5）
